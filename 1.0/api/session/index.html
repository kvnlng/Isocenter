Session API#

Session is the entry point: from isocenter import Session. It is the class isocenter.session.DicomSession, rendered below. Its constructor and every method on this page are frozen at 1.0 (API stability). So are the attributes in its table, except store_backend, which is tier 2. This page lists the methods in pipeline order, ingest → examine → config → audit → anonymize → redact → verify → export → report. compact, release_memory and close come last. Results and errors says what the methods return and raise.

Session#

Session(persistence_file=None)#

The session: an indexed store of DICOM files and the de-identification pipeline over it.

Import it as from isocenter import Session. Use it in a with block, or call close(), because an open session holds a worker pool and two threads.

Attributes:

Name

Type

Description

store

DicomStore

The object graph. store.patients is the List[Patient] of Patient -> Study -> Series -> Instance.

configuration

IsocenterConfiguration

The configuration that audit(), anonymize(), redact() and export() apply.

store_backend

SqliteStore

The session’s SQLite store. Its get_audit_* methods read the audit trail.

persistence_file

str

The store’s path, or ":memory:".

Open the session store at persistence_file, creating it if needed.

The store is the SQLite file and a pixel file beside it (by default isocenter.db and isocenter_pixels.bin). It holds the original identifiers and pixels of everything ingested. Keep it where you keep the source data, on a local filesystem. The store uses SQLite’s WAL mode and flock locks, which a network filesystem does not dependably support.

When the store’s filesystem is a known network type (NFS, SMB, Lustre, GPFS and others), one WARNING log line says so, and the store opens anyway. Until export(), the session writes only the store, isocenter.log and the files that you ask for (a configuration, a key).

When a file named isocenter.key exists in the current working directory, the session calls enable_reversible_anonymization() with it. The path is resolved to an absolute path at construction. With no such file, reversible anonymization stays off and no key is created.

Parameters:

persistence_file (str) – Path to the SQLite database file for session persistence. The default is ISOCENTER_DB_PATH, then "isocenter.db". ":memory:" is accepted and is part of the frozen surface. With it, the index lives in memory, and the pixel sidecar lives in a temporary file that the store unlinks on close(). On such a store, redact() runs in threads on every interpreter, because its worker writes to the store and a process cannot share an in-memory database. With ISOCENTER_MAX_TASKS_PER_CHILD set, recycling overrides that and the call fails. See that variable on the Environment Variables page.

Raises:

ValueError – If isocenter.key in the working directory is empty, is not a Fernet key, or is not a regular file (a directory, a FIFO). The message names its absolute path. The threads that the session had started are released before the error is raised, as they are for any exception from construction.

ingest(directory: str)#

Ingest every DICOM file under a directory into the session store.

It walks directory recursively, reads each DICOM file into the Patient -> Study -> Series -> Instance hierarchy, and saves the session when it finishes.

A file that cannot be ingested does not raise. It is counted in the returned summary, and it gets an ERROR audit row that names the path and the reason. That row bars a PASS grade. Check the return value, because a run that rejected files completes normally.

A file can be refused after its pixels or waveform samples were read (Linkage Failed). Such a file may leave them in the sidecar as dead space until compact(), which reclaims them in a store that holds at least one instance (#943).

A file linked by something that is not one text value. A file is linked by its SOP Instance UID, Study Instance UID, Series Instance UID and Patient ID. A file is rejected as above when it holds two values in any of them (#747). It is also rejected when it states a VR for one of them that is not text (OB, US, DS, SQ and the like, in an Explicit VR file, #1022). Only that file is rejected. Its reason names the element and the count or the VR, never a value, and nothing of the file is in the sidecar. Until #1022, a SOP Instance UID or Patient ID under such a VR made this call raise ValueError from its save and store nothing.

Hidden files. A file that the walk of directory finds, whose name starts with . (.DS_Store, AppleDouble ._*), is not read. It is counted in IngestSummary.hidden, and the console summary prints the count, with no audit row. A directory whose name starts with . is walked, and a file named directly as directory is read whatever its name.

A file that ends the worker process reading it (the out-of-memory killer, a decoder crash, SIGKILL) is read again alone on a fresh worker. It is rejected only if it ends that worker too. Files already read are kept. A death that does not recur costs no file and logs one WARNING line.

When a worker ends, the pool’s other workers are sent SIGTERM. A worker that is still running 10 s after ingest() finds the pool broken is sent SIGKILL, and one WARNING line names it. A worker of a script that handles SIGTERM can be such a worker. If fresh workers cannot run at all, every file left is rejected as “Not read”, with a reason that names the usual causes (a script without the if __name__ == "__main__": guard among them). The call then returns. Any other failure of the worker pool raises.

Duplicate SOP Instance UIDs. A file is declined when an instance in this session already holds its SOP Instance UID. That instance was ingested earlier in this call, by an earlier call, or loaded from the store. For a declined file:

  • the instance is kept

  • the file is not read into the store

  • the file is counted in IngestSummary.declined

  • a WARNING audit row names the UID, the file, and the file that the instance was ingested from

An instance that the session already holds is always kept over a new file. Among files new to this call, the one whose path sorts first is kept, whatever order the filesystem lists them in. The sort is on the path string as walked (os.path.join of the directory and the name), which is the string that the WARNING row prints. A declined file is not recorded as imported, so a second ingest of the same folder declines it again.

A study another patient holds. A file that carries a Patient ID is declined the same way, and in the same order, when a patient with a different Patient ID already holds its Study Instance UID (#745). Its WARNING row names the file and the instance, never a Patient ID. A file that carries the original ID of the patient whose study anonymize() renamed belongs to that patient, and is linked. A file with no Patient ID belongs to that patient too, and is linked.

Byte order. A big-endian source’s values in words wider than a byte (OW, OL, OF, OD, OV and the waveform samples) are stored little-endian, as its pixels are. A value that cannot be converted whole (a UN value, a length that is not a whole number of words, samples with no usable Waveform Bits Allocated) is kept as read, and it gets one WARNING audit row per element.

Environment. ISOCENTER_FORCE_THREADS and ISOCENTER_MAX_TASKS_PER_CHILD have no effect, because ingest runs on the session’s own process pool, which has no threads mode and never recycles a worker. When either is set, each call that has files to read logs one WARNING. ISOCENTER_MAX_WORKERS is read on every call, and the pool is rebuilt when the width has changed. An unchanged width rebuilds nothing. While another ingest() in this session is running on the pool, a changed width is reported in one WARNING, and this call runs at the pool’s current width.

Concurrency. compact() on any thread of this session raises while an ingest runs. While a compact() is saving or rewriting, this call waits (bounded, see Raises) and then proceeds. A file whose pixels cannot be written in that time is rejected like any other failed file, with an ERROR audit row that names the path and the reason.

Parameters:

directory (str) – The path to the directory containing DICOM files.

Returns:

How many files reached the store, and (path, reason) for each one that did not.

Return type:

IngestSummary

Raises:

RuntimeError – If the ingest cannot start within 180 s because a compact() is still saving or rewriting the sidecar.

save(sync: bool = False)#

Persist the current session state to the store.

Without sync=True, the save is queued and this method returns before the save is written, so a failure is not raised here. The failure is logged at ERROR, and the next call that drains the queue then hears it. audit(), redact(), lock_identities() and lock_identities_batch() run the failed save again themselves and raise what it raises. A failure that has passed heals there silently. save(sync=True), export() and compact() save the session themselves and raise the same way.

A session can close, or its process can exit, with a failed background save that no later save healed. Then one ERROR audit row keyed SESSION is written, so a later session’s report on the store grades REVIEW_REQUIRED (#941).

Parameters:

sync (bool) – If True, block until the save is complete. A synchronous save first waits for the persistence manager’s queue, and never returns early: a background save that does not finish blocks it.

examine()#

Prints a summary of the session contents and equipment.

create_config(output_path: str)#

Generates a unified configuration file (scaffold) in YAML format.

It reads the session inventory, pre-fills redaction rules for any machine that the shipped knowledge bases recognise, adds the default PHI tag policy, and writes the result as commented YAML.

Parameters:

output_path (str) – Where to write the generated YAML. A .yaml suffix is appended if missing.

The phi_tags section names the session’s own base, as save() does. It holds every rule that differs from the rules of that base, compared whole (#741). The file names the base as privacy_profile: none for a session under none, as the external file’s path for an external profile, and as the pinned name for a built-in. The floor is the one exception. It is spelled privacy_profile: basic@2026c, with the research defaults as editable lines, and that loads to the same rules. The file loads to the session’s phi_tags.

Raises:

  • ValueError – If configuration.date_jitter is a range that the loader would refuse in the file (#731). Also save()’s refusals: if phi_tags lacks a rule that its base supplies (#741), or if output_path is a file that declares a newer version minor than this library’s (#784). Also if configuration.burned_in_text is a policy that the loader would refuse in a file (#1108). In each case, nothing is written.

  • OSError – The write’s own error, after it is logged (#741).

load_config(config_file: str)#

Load a configuration file as the session’s configuration.

A load changes no data. preview_config() shows which instances its redaction rules match. audit(), anonymize() and redact() apply it.

Parameters:

config_file (str) – Path to the YAML configuration file.

Raises:

  • FileNotFoundError – If config_file does not exist.

  • ValueError – If the file fails validation: not .yaml/.yml, YAML syntax, a root that is not a mapping, a version this library does not read, a key the schema does not have at any level, a value of the wrong type, an unknown privacy_profile (including a <profile>@<edition> this version does not ship), an unknown action, a phi_tags, date_jitter or machines of the wrong shape, an invalid machine rule, or a phi_tags rule the pipeline cannot honour. After either error the configuration is exactly what it was before the call.

preview_config()#

Runs a dry run of the currently loaded configuration.

It checks the active redaction rules against the current session inventory, and prints a summary of the instances that the rules would affect (match). It does not change any data.

audit(config_path: str = None) → PhiReport#

Scan every patient in the session for PHI under a tag policy.

The policy is the file at config_path when one is given, and otherwise session.configuration.phi_tags. The scan runs in parallel worker processes.

Before the scan, two Patient objects that hold one Patient ID are merged into the one that was in the session first. So store.patients can get shorter, as after anonymize().

The scan records every status with the policy that it ran under. That is the configuration’s policy, or, with config_path, that file’s rules under this session’s remove_private_tags. An entity whose status is unchanged but whose policy differs is recorded again, so the next save() writes it.

Parameters:

config_path (str, optional) – Path to a configuration file whose PHI rules to scan with.

Returns:

The findings: iterable, indexable, and convertible with to_dataframe().

Return type:

PhiReport

Raises:

  • ValueError – If the file at config_path fails any check that load_config() makes. If the policy (that file’s, or configuration.phi_tags) holds a rule that the pipeline cannot honour. With no config_path, if configuration.date_jitter is a range that the loader would refuse in a file (#731). In each case, it is raised before a project secret is created.

  • RuntimeError – If patients that share a Patient ID were de-identified under different date-offset schemes, so they cannot be merged. It is raised after the policy is validated, and before anything is scanned or a project secret is created. Also on a store that holds dates shifted under a project secret that it no longer has.

  • Exception – If a background save() failed and still fails. The entry drain runs that save again and raises what it raises (the store’s named TypeError or ValueError, an OSError, the sidecar gate’s RuntimeError), before anything is scanned. A failure that has passed is saved there, and nothing is raised (#941).

anonymize(findings: List[PhiFinding] = None)#

Apply the remediation each PHI finding proposes (tag anonymization).

With findings, only those findings are remediated. An empty list, tuple, PhiReport or iterator applies nothing and returns 0, because a filtered report that matched nothing is not a request to remediate everything. Only findings=None, or no argument, runs a full audit() under the current configuration and remediates every finding that it raises. An empty call still reads the store’s project secret, so a store that has lost the secret refuses and does not return 0.

Nothing outside session.store is written. A finding whose entity is itself in the graph is acted on as it is, with one exception. For a REMOVE_TAG, “already gone” is read on the object at the finding’s address, and the finding declines where that object and entity differ. Any other finding is resolved against the live graph at its entity_uid and entity_path, and acts on the object found there. That entity_uid may be an instance’s UID from before redact(), or a patient’s original Patient ID after the pseudonym that this store minted for it. Because the finding acts on the live object, a report kept across close() and a reopen cleans the graph that export() writes.

A finding whose address names no single object declines. A finding inside a sequence that a pass already removed or emptied is satisfied. A Patient ID is written, and a date is shifted, only with a value that belongs to the live patient that holds it (this store’s pseudonym, and an offset seeded on that patient under its own scheme). Otherwise the finding declines. The findings passed are not modified.

A patient, study or instance edited after its last scan and before this pass is not stamped by the pass. It keeps the status that the scan left, and still reads UNSCANNED afterwards. So it grades under condition 8 until audit() reads the edit (#752).

Two patients can be left holding one Patient ID (a study ingested under a patient’s original ID after that patient was anonymized). They are merged into whichever was in the session first, and the other is removed from store.patients.

Parameters:

findings (List[PhiFinding], optional) – Specific findings to clean.

Returns:

How many remediations were applied. Failures are logged and excluded, so a caller can tell a clean run from a partial one.

Return type:

int

Raises:

  • ValueError – If configuration.date_jitter is a range that the loader would refuse in a file (#731). It is raised first, before anything is scanned or shifted.

  • RuntimeError – If two patients left holding one Patient ID were de-identified under different date-offset schemes. It is raised at the merge, after the remediations are applied. It cannot occur on a graph that the library built, but it can occur on one built in user code.

  • Exception – With no findings, whatever the starting audit() raises, including a failed background save() that still fails (#941). It is raised before anything is remediated. Given its findings, the method makes no such call and does not raise that.

enable_reversible_anonymization(key_path: str = 'isocenter.key')#

Turn on reversible anonymization with the key file at key_path.

It loads the key when a file is there. This call never creates the key file, and neither does recovery. The first lock_identities() that writes a token creates it when none exists. So a mistyped path before recover_patient_identity() fails there with FileNotFoundError, and does not mint a key that the data was never locked under.

Parameters:

key_path (str) – Path to the key file.

Raises:

ValueError – If the file at key_path is not a Fernet key, or is empty, or the path is not a regular file (a directory, a FIFO). The message names the path. A failed enable caches nothing, and the session stays open and usable. Fix the file and enable again.

lock_identities(patient_id: str, persist: bool = False, *, verbose: bool = True, tags_to_lock: List[str] | None = None) → List[Instance] | LockingResult#

Encrypt each instance’s original identifiers into an identity token carried in the instance, for reversible anonymization.

The token is written into the Encrypted Attributes Sequence (0400,0500), under the key that enable_reversible_anonymization() names. Values are captured from each instance, and one token is written per distinct set of them. So under the default tags, a patient with several studies carries about one token per study. Each instance’s token holds that instance’s own values.

If recovery is required, call it before anonymize(). After anonymize(), the identifying tags no longer hold their original values, and the lock refuses to capture what a remediation wrote.

Anything but a str (an iterable of Patient IDs, a PhiReport or a list of findings) is handed to lock_identities_batch(), with the same persist, verbose and tags_to_lock. auto_persist_chunk_size is that method’s own argument.

Refusals. The lock raises RuntimeError and writes no token when the patient cannot be locked as asked:

  • A remediation wrote a value that the lock would capture (ANONYMIZED, ANON_..., a rule’s value:, a shifted date).

  • anonymize() emptied or removed a tag that the lock names, on any of the patient’s instances. The message names the tags_to_lock that works without that tag. Where other instances still hold a value there (a study or series ingested after the pass), the message counts both, and that lock stashes the tag for none of them.

  • A re-lock would lose a value that the existing token holds.

  • The patient carries an identity token that this library wrote, and one of these is true of the token: the key at the path given to enable_reversible_anonymization() does not decrypt it, it opens to no identity record, or it is in the layout that releases before 1.0 wrote, which 1.x does not read.

  • A re-lock over a token that this store did not write (one that arrived inside a file, or one that a release before 0.9.8 wrote) would change a value that the token holds. The message names the tag, which need not be one that tags_to_lock names. The way through is recover_patient_identity(..., restore=True), followed by a lock.

  • A value that the lock would capture is one that no token can hold (bytes). The message names the tag.

  • Patient’s Name is blank under a rule of EMPTY or REMOVE on it.

  • The patient holds a Patient ID (or a Patient’s Name), and every instance’s copy of 0010,0020 (or 0010,0010) is present and blank. The message names the tag. The token would restore the patient without it (#761).

  • The patient has instances, and any of them holds no value in any tag that tags_to_lock names (or tags_to_lock names none). The message counts them. For 0010,0010 and 0010,0020, the lock reads the patient’s value when an instance holds none. A tag held blank is a value, except as the refusal above says. A patient with no instances locks as 0 instances.

Each of these is judged on every instance’s own values, so a value that a pass wrote on any study refuses the lock. An existing token is judged against the first instance that carries it. Before any patient is planned, the lock also refuses when no key file exists at the path and an instance in the session carries a token that this library wrote. No key is created then. Given a list or a report, every patient is checked first. If any is refused, one error lists each refused patient, and no patient is locked.

No message carries a Patient ID. A message says “this patient”, its advice spells the ID <its Patient ID>, and a replaced Patient ID is described, not quoted.

Only a lock that writes a token creates the key file (the first such lock under a path with none). It creates the file after every patient is planned, already written and with mode 0600. A lock that writes no token (refused, no patient found, or none with an instance) creates no key file (#813).

Parameters:

  • patient_id (str) – The ID of the patient to lock. Anything that is not a str (a list, set, frozenset or iterator of IDs, or a report) is handed to lock_identities_batch().

  • persist (bool) – If True, writes each instance’s token immediately into the row that the store holds for it. An instance that the store holds no row for raises (see RuntimeError). If False, returns the modified instances for a later save().

  • verbose (bool) – If True, logs debug information.

  • tags_to_lock (List[str], optional) – The tags whose original values are embedded. When omitted: PatientName, PatientID, PatientBirthDate, PatientSex and AccessionNumber.

Returns:

A list of modified instances.

Return type:

Union[List[Instance], LockingResult]

Raises:

  • RuntimeError – If reversible anonymization is not enabled, or for a refusal above, before any token is written. Also, with persist=True, if some instance’s current SOP Instance UID has no row in the store to write its token into. This happens for a patient built by hand and never saved, or for a UID that regenerate_uid() moved (as redact() does) since the last save. That error is raised after the tokens are embedded. They are in memory and marked modified, so a later save(sync=True) stores them. This write stored none of them, and one ERROR audit row gives the counts. ingest() writes the rows itself, and the lock drains a save queued by save() before it embeds anything. So neither ingest-then-lock nor save()-then-lock raises it.

  • TypeError – If patient_id is not a str and is not a selection that lock_identities_batch() accepts: None, bytes-like, not iterable, or an iterable that holds an item that is neither a str nor a finding. It is raised before the key is loaded or created.

  • ValueError – If the key file at the path is empty (the message names the path) or is not a Fernet key. Neither result is cached, so a later call reads the file again.

  • sqlite3.Error – With persist=True, if the store refused the write. The instances already carry the new token in memory, marked modified, so a later save() writes them. This write stored none of them, and one ERROR audit row says so. The row speaks for the write, not for the store, which keeps whatever an earlier write put there. Given a list or a report, the batch form’s sqlite3.Error applies.

  • Exception – If a background save() failed and still fails. The lock’s drain runs that save again and raises what it raises, before any token is embedded. A failure that has passed is saved there, and nothing is raised (#941). The batch form does the same.

lock_identities_batch(patient_ids: List[str] | PhiReport | List[PhiFinding], auto_persist_chunk_size: int = 0, tags_to_lock: List[str] | None = None, *, persist: bool = False, verbose: bool = True) → List[Instance] | LockingResult#

Lock the identities of several patients. See lock_identities().

Parameters:

  • patient_ids (Union[Iterable[str], PhiReport]) – The patients to lock: an iterable of Patient IDs (read once, so an iterator works), a PhiReport, or an iterable of findings, which may be mixed with IDs. It is read as every other method reads patient_ids, except that None is refused. There is no spelling for “lock every patient”, and the report that audit() returns locks every patient that its scan found.

  • auto_persist_chunk_size (int) – If > 0, persists changes and releases memory every N instances, and the call returns an empty list.

  • tags_to_lock (List[str], optional) – Passed to every patient’s lock. When omitted, lock_identities()’s five default tags apply.

  • persist (bool) – Passed to every patient’s lock: each patient’s instances are written as they are locked. With auto_persist_chunk_size > 0 as well, an instance is written twice (with its patient, then with its chunk), which is redundant, not wrong.

  • verbose (bool) – Passed to every patient’s lock: one debug line per patient.

Returns:

All modified instances, or an empty list when auto_persist_chunk_size > 0.

Return type:

Union[List[Instance], LockingResult]

Raises:

  • RuntimeError – If reversible anonymization is not enabled, or if any patient found cannot be locked as asked (the refusals that lock_identities() lists). Every patient is checked before any is locked. So the one error lists each refused patient with its own message, in Patient ID order, and no patient is locked, whatever persist or auto_persist_chunk_size says. A Patient ID that matches no patient is logged, not raised. The promise is about refusals, not about the store (see sqlite3.Error). No message names a patient. Each refusal is prefixed [n of m], its place among the m patients found, in Patient ID order. So the refused patient is sorted(ids that matched a patient)[n - 1]. The refusal raised before any plan (no key file, and a token that this library wrote somewhere in the session) is one message with no number, and it creates no key.

  • TypeError – If patient_ids is None, is a bare str (the single-ID spelling is lock_identities(patient_id)), is bytes-like, is not iterable, or holds an item that is neither a str nor a finding. The message names such an item by its position and type, never by its value. It is raised before the key is loaded or created, and before any patient is planned.

  • ValueError – If the key file is empty or is not a Fernet key, as for lock_identities().

  • Exception – If a background save() failed and still fails. The lock’s drain runs that save again and raises what it raises, before any token is embedded, as for lock_identities() (#941).

  • sqlite3.Error – If a store write failed while tokens were being persisted (persist=True writes per patient, auto_persist_chunk_size per chunk). It is raised after one ERROR audit row. A store write that found no row for an instance raises RuntimeError instead (see lock_identities()), with the same shape and timing. Both are raised after the tokens are embedded, unlike the refusals above. Nothing is rolled back across writes. Patients written before the failure stay locked in the store. The failed write stored none of its instances (they hold their new tokens in memory, marked modified, and a later save() writes them). The patients after it in Patient ID order are not locked. One write is one transaction. With both persist=True and auto_persist_chunk_size, each instance is written with its patient and again with its chunk. So where a chunk write fails, its instances were already stored with their patients.

recover_patient_identity(patient_id: str, restore: bool = True) → Dict[str, Dict[str, Any]]#

Decrypt a patient’s identity tokens and return the identity they hold. With restore=True, also write it back onto the patient.

Which token speaks for the patient. It is the first token of ours in study, series and instance order. A study without a token, or with an Encrypted Attributes Sequence that this library did not write, is walked past. For a patient with a Patient ID, a first token that holds a blank Patient ID is passed over for the first token that holds a non-blank one, when there is one. For a subject with no Patient ID, its first token always speaks, and the subject keeps its key.

Every distinct token is opened before anything is written, with restore=False too. A token of ours on any study that this key cannot open, or that holds no record, raises and writes nothing. So restore=False also checks that the patient is recoverable under this key. Every failure raises. Nothing is printed, and no message names a Patient ID.

What restore=True writes. Every instance of the patient in memory takes the locked identity tags from the token that it carries. The restore is recorded, so a later save() stores it. A patient that already holds the restored Patient ID is merged into whichever of the two was in the session first.

  • Only the locked tags are put back. Every other date stays shifted by the patient’s offset, so intervals are intact and a later audit() does not shift it again. A date among the locked tags is put back like any locked tag, and a later audit() raises it again.

  • When the restored value reads as a date, a restored Study Date is also put back on each Study, from that study’s own token. export() reads it there. A blank or unreadable value leaves the Study as it is, with one WARNING per such study that carries no date.

  • An instance that carries no token takes only the patient-level identifiers of the token that speaks for the patient. These are group 0010, which includes Patient’s Age, Size and Weight, and so may be another study’s. The instance keeps its other locked identifiers as the pass left them, and one WARNING gives the count. For a patient with no Patient ID, such an instance keeps a non-blank Patient ID of its own, and does not take the token’s blank one. A second WARNING counts those instances.

  • Where tokens disagree on Patient’s Name or Patient ID, each instance keeps its own and the Patient takes the speaking token’s, with a WARNING. A token whose Patient ID is blank does not disagree on it.

Parameters:

  • patient_id (str) – The Patient ID the patient holds now (normally its pseudonym).

  • restore (bool) – If True, write the recovered identity back, as above. If False, write nothing.

Returns:

redact(show_progress=True, force=False)#

Apply the configured pixel redaction zones to every matching image.

It uses session.configuration.rules. Every image of a series that a rule covers, by its Device Serial Number or by match:, has each of the rule’s zones set to zero. This changes pixel data in memory (and the sidecar, for persistence). Call save() afterwards to persist it.

An image that several rules match (an exact rule and "*") is redacted once, with the zones of every matching rule. A redacted instance takes a new SOP Instance UID. The UID is derived from its source SOP Instance UID and the zones of every rule that matches it, whatever order the work runs in.

The burned_in_text policy (configuration.burned_in_text, #1108). When the configuration holds one, this call also reads every instance in the policy’s scope, serial or not, after the zones its rules hold. It reads with OCR by tesseract, or with the text detector under detector: db. The scope is flagged, modalities or all (#1121). An instance out of scope is neither read nor gated at export. The call records the boxes of the text that it finds at min_confidence or above (under tesseract, with two letters or digits), never the text itself. The policy’s action decides the rest:

  • redact blanks each box, padded, on its own frame, in the same task as the zones. The instance’s UID is derived from the zones and the boxes.

  • report writes one WARNING audit row per instance with text, and changes no pixel.

  • withhold changes nothing here, and export() withholds each instance with text.

The record names, by a digest, the pixels that the read saw. An instance already read under this threshold and these zones, whose pixels still match the digest, is not read again unless force=True. A redacted instance is read once more, which moves the digest to its redacted pixels. A failure of that read writes a WARNING row and leaves the instance unchecked. Text still found writes a WARNING row.

An instance that only this policy redacted carries DERIVED and the derivation code, but keeps Burned In Annotation as the source had it. Every pass writes one REDACTION row with its counts and what read: the tesseract version, or under detector: db the detector model and the OpenCV version (with the tesseract version too under a narrowed target). redact_by_machine() does not run the policy.

Concurrency. compact() on any thread of this session raises while a pass runs. While a compact() is saving or rewriting, this call waits (bounded, see Raises) and then proceeds. A worker whose pixels cannot be written in time comes back as a failed redaction, with an ERROR audit row.

Parameters:

  • show_progress (bool) – If True, displays a progress bar.

  • force (bool) – Redact again the instances already redacted under this configuration, instead of skipping them. Every instance that the rules match is redacted again. Its SOP Instance UID is derived again from its source SOP Instance UID and the zones of its matching rules. Unchanged zones give the UID and exported filename that it already has, and other zones give another. file_path becomes None either way. Under a burned_in_text policy, also read every instance again, and keep every box that its record held beside the ones found now.

Returns:

How many instances had at least one configured zone, or one burned_in_text box, applied to their pixels. An instance that a rule matched but whose every zone fell outside the image is not counted. A zone with no area fails its instance, and the pass raises RedactionError, so that instance is never counted. Zero means that nothing was redacted: no rules loaded and no burned_in_text policy, no image matched one, every match was already redacted under this configuration, no zone landed, or the policy’s action is report or withhold.

Return type:

int

Raises:

  • RedactionError – If any instance’s zone could not be applied. It is raised at the end of the pass, not at the first failure. By then the instances that could be redacted are redacted, the failures are already ERROR rows in the audit log, and the console summary has been printed. So a caller that catches it still has a correct object graph and a compliance report that grades REVIEW_REQUIRED. .failures carries (sop_uid, detail) per failed instance. compact()#

Rewrite the pixel sidecar (_pixels.bin) to reclaim the space of frames no instance references, and point every loader at the new offsets.

This is an expensive I/O operation. It starts with save(sync=True), so it waits for a background save that is running.

Two behaviours are contract, observable from any thread of this session:

  1. It raises RuntimeError while a redact() or ingest() pass is open on the same store. The check comes first, before the leading save, so a refused call has done nothing.

  2. A redact() or ingest() that starts while it is saving or rewriting waits, bounded by 180 s, and then proceeds.

Every frame writer, and this method for the whole rewrite, holds a cross-process lock beside the sidecar, so a frame written while compaction runs lands in the compacted file. A writer that cannot take the lock within 180 s raises RuntimeError. A background save that expires this way is logged as Background save failed, and its instances stay unsaved for the next save.

The rewrite holds the lock for its whole length, about 0.2 s per GB on local SSD. A close() whose persistence worker is queued behind a compaction longer than 30 s reports that worker as wedged.

Raises:

RuntimeError – In three cases: while a redact() or ingest() pass is open on this store, when a save is still queued on the persistence manager after the leading save, or when the sidecar lock cannot be taken within 180 s.

release_memory()#

Release cached pixel and waveform data from every instance.

Each instance goes through Instance.unload_pixel_data(), with its precondition. So an array replaced through set_pixel_data() and not since written is kept. An array changed in place is not tracked, so it is dropped here, and the next get_pixel_data() returns the frame from before the change. Only an array that a save has already written can be changed in place, because a frame read from a file or from the store is read-only.

Cached waveform samples are int16 of shape (num_samples, num_channels): about 80 KB for a 10-second 12-lead, about 104 MB for a 24-hour 3-channel Holter.

Its progress bar follows ISOCENTER_SHOW_PROGRESS.

close()#

Shut the session down: the persistence-manager thread, the audit thread that owns the sqlite connection, and the process pool. A session that is never closed leaks its worker subprocesses for the life of the process. If the pool is broken because one of its workers ended outright, a worker of the pool that is still running 10 s after close() finds the pool broken is sent SIGKILL, and one WARNING line names that worker.

All three steps run even if an earlier one raises. If more than one fails, the first failure is raised and the later ones are logged. A second call is safe. It repeats the shutdown messages and the unsaved-instances WARNING.

An export that withheld everything returns an empty summary and does not raise, because nothing failed. An instance outside subset is not withheld, because it was never asked for. Under a burned_in_text policy (#1108), the export also reads with the policy’s reader (OCR by tesseract, or the text detector under detector: db) every planned instance that holds pixels, as it is about to be written, after the configured zones. That read, not the record of the last redact(), decides the instance. An instance with text found is withheld under redact and withhold, and written under report. An instance with nothing found is written. An instance whose read failed is withheld under redact and withhold, and written under report. Each of these writes one WARNING row that names the instance, the count and the frames, but never the text. The read changes nothing in the session. It redacts no pixel and moves no UID. If a reader that the policy needs cannot run, it raises OcrUnavailableError before the scan, the save and any row. Tesseract (the ocr extra and the binary) is needed under detector: tesseract or a narrowed target, the text detector under detector: db (TextDetectorUnavailableError), and the names model when target names names (NlpUnavailableError). Under detector: db with target: any, tesseract is not needed.

  • check_reversibility (bool) – If True (the default), warn when the files that this export wrote still carry the encrypted originals that lock_identities() embeds, and record the disclosure in the audit log. The check runs after the write, against what reached disk. Anyone who holds the key can recover those identities, and a recipient of the cohort cannot see this for themselves. Passing False silences the warning and skips the audit row. The export itself is the same either way, because this check reports and does not withhold.

  • patient_ids (Iterable[str], optional) – Limit export to specific Patient IDs. Only None, or the parameter omitted, means every patient. An empty list, tuple or set is a filter that selected nobody, and nothing is written. An iterator is read once before the walk. A bare str (wrap one ID in a list), a bytes-like value, a non-iterable, or an element that is not a str is refused with TypeError before anything is flushed or written. An ID that no patient in the session holds selects nothing. It is counted but never named, in one WARNING log line and one WARNING audit row, so the report grades REVIEW_REQUIRED. The patients that do match are exported as asked. After anonymize(), a patient is selected by its replacement ID. The wfdb format and get_cohort_report() read patient_ids in the same way.

  • show_progress (bool) – If True, shows progress bar.

  • subset (Union[str, pd.DataFrame, Iterable[str]]) –

    Filter the export with one of these:

    • A pandas query string, run against get_cohort_report(expand_metadata=True).

    • A DataFrame. It is read by the first of SOPInstanceUID, SeriesInstanceUID, StudyInstanceUID and PatientID that it carries. One with none of them raises ValueError.

    • Any other iterable of UIDs at any level (list, tuple, set, a generator), read as patient_ids is.

    Only None means no filter, and an empty one selects nothing. A bytes-like value, a non-iterable, or an element that is not a str raises TypeError before anything is scanned, flushed or written. A value that names nothing in the session at any level (as itself, as the UID that this store replaced it with, or, for a SOP Instance UID taken before redact(), as the instance’s redacted UID) is counted by position and never named, in one WARNING log line and one WARNING audit row, so the report grades REVIEW_REQUIRED. The rest is exported as asked. A query cannot name anything that the session lacks, so it is never counted.

  • verify_readback (bool) –

    If True, each worker reads again the file that it just wrote, before the file is published under its real name. The worker compares the file with what it meant to write, in this order:

    • Rows, Columns, SamplesPerPixel, NumberOfFrames and BitsAllocated, against the dataset that it serialized.

    • The file’s PhotometricInterpretation, against the transfer syntax that the file itself carries. The syntax must admit it, and it must be a single value.

    • Every pixel sample, decoded the way ingest() decodes it and compared bit for bit with the samples written, after redaction.

    • A DICOM waveform’s WaveformData bytes.

    The stored samples are compared, not a colour conversion of them. A file labelled YBR_FULL or YBR_FULL_422 over samples that are not unsigned 8-bit is also decoded with pydicom’s colour conversion, as ingest() decodes it. It fails when that decode raises, which it does for 16-bit and int8 samples. A value outside the declared BitsStored fails an uncompressed file, because every conformant reader masks it (-3024 at BitsStored 12 reads as 1072).

    Passing True can cost a file that the default export delivers. By default, a Photometric Interpretation that the written syntax does not admit (YBR_ICT or YBR_RCT on an uncompressed file, YBR_PARTIAL_422/_420 on any file that this exporter writes) is written exactly as the instance declared it, with a WARNING audit row and a REVIEW_REQUIRED grade. With True, that instance fails, gets an ERROR row, and no file for it reaches the output folder. The reason names the label, the syntax and a remedy. The check does not ask whether the samples are really in the colour space that the label names. RGB over YBR samples passes, and so does a file under a transfer syntax that the check has no row for.

    An unreadable or undecodable file, or any mismatch, fails that instance’s export. The instance is counted out of “Instances Written”, gets an ERROR audit row, and takes the grade to REVIEW_REQUIRED. When every instance fails, the call raises ExportError. This option is off by default because it costs a second parse and a full decode per instance. That is about twice the time of a default (JPEG 2000) export, and little more for an uncompressed one. Each worker holds one more decoded array while it checks.

Returns:

What reached disk and what did not. It is empty when nothing was attempted.

Return type:

ExportSummary

Raises:

  • TypeError – If patient_ids or subset is of a type that the selection does not take. It is raised before anything is flushed or written.

  • ValueError – If subset is a DataFrame that carries none of SOPInstanceUID, SeriesInstanceUID, StudyInstanceUID and PatientID, or a query string that does not run against the cohort report. Also if configuration.burned_in_text is a policy that the loader would refuse in a file (#1108). It is raised before the pre-export scan and the save.

  • OcrUnavailableError – If check_burned_in=True under a burned_in_text policy, and a reader that the policy needs cannot run (#1108): tesseract (the ocr extra and the binary) under detector: tesseract or a narrowed target, the text detector under detector: db (TextDetectorUnavailableError), or the names model when target names names (NlpUnavailableError). Under detector: db with target: any, tesseract is not needed. It is a RuntimeError, raised before the tag scan, the save, any row or any file.

  • ExportError – If every planned instance failed (nothing written and at least one failure). It is raised last, after the audit rows and the EXPORT row are written. A partial export and an empty plan return a summary instead.
