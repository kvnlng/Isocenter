IngestSummary(ingested: int = 0, failures: List[Tuple[str, str]] = list(), declined: int = 0, skipped: int = 0, hidden: int = 0)#

What ingest() did with each file it found.

A file takes exactly one of five routes. A declined file is not recorded as imported, so a second offer of it declines it again.

Attributes:

Type

Description

(path, reason) per rejected file, the same pair that its ERROR audit row carries.

Files refused because the session already holds their SOP Instance UID, as another instance’s UID or as a redacted instance’s UID before redaction. It also counts files whose Study Instance UID is held by a patient with a different Patient ID (#745). Each has a WARNING audit row and is not read into the store.

ExportSummary(written_uids: List[str] = list(), failures: List[Tuple[str, str]] = list())#

What export(format="dicom") wrote, and what it did not.

Attributes:

Name

Type

Description

written_uids

List[str]

The SOP Instance UID of each instance that reached disk, and nothing else. An instance with no UID is not written and is in failures. An instance whose UID cannot name a file (export_file_name) is in failures too, under that UID. When the volume resolves two file names to one file, one instance’s write replaces the other’s file (#1020). From session.export(), the instance whose file was replaced is in failures too, and the instance that the file holds is here.

failures

List[Tuple[str, str]]

(entity_uid, details) per instance that did not reach disk, each with an audit row. The instances of one replaced file share one row, which names them all.

written

int

Files that reached disk, counted over distinct UIDs. Two instances that share a UID write one file.

failed

int

len(failures).

Findings#

PhiReport(findings: List[PhiFinding], failures: List[Tuple[str, str]] | None = None)#

A container for PHI findings that supports analysis and export.

A report works like the list of findings it wraps: you can iterate, index and measure it (len(report), report[0], for finding in report). It also adds DataFrame export.

Attributes:

Name

Type

Description

findings

List[PhiFinding]

The findings, one per report line.

failures

List[Tuple[str, str]]

(entity_uid, reason), one per instance that a pixel scan could not read in full. Either the instance’s pixels could not be loaded, or OCR raised on at least one of its frames. scan_pixel_content() fills it. An instance that failed on some frames keeps the findings of the frames that were read. It is always a list, never None. The list from audit() is always empty, because a failure in its workers raises instead.

Identity locks#

LockingResult(iterable=(), /)#

What lock_identities() returns. It is a list of the Instance objects that received an identity token. Its repr is one line (<LockingResult: N instances secured>), not every instance.

Exceptions#

RedactionError(failures, attempted)#

Redaction did not remove what it was asked to remove.

Raised after the whole pass, not at the first failure: the instances that could be redacted are redacted, and the failures are already in the audit log, so a caller that catches this still gets a compliance report that grades REVIEW_REQUIRED.

A RuntimeError subclass, so except RuntimeError catches it; its own class tells it from the export path’s bare RuntimeError exceptions, which mean nothing was written, where this means something unsafe is still in the graph.

Parameters:

  • failures (list) – (entity_uid, details) pairs, kept as self.failures.

  • attempted (int) – How many instances the pass targeted, kept as self.attempted.

ExportError(failures, attempted, folder=None)#

The export delivered nothing.

session.export() raises it when zero of N planned instances reached disk and at least one failed. This holds in both formats: the DICOM path, and WfdbExporter.export, where N is the waveform records attempted. The message says “instances” in both. A WFDB record is written from one waveform instance, and that instance’s UID names its failure, as for DICOM. It is not raised on a partial export.

One case leaves a file behind (#1020). In that case, every planned instance was written under file names that the volume resolved to one file, and that file could not be read back as any of them. No instance is reported as written, so this error is raised, and the folder holds that one file. The ERROR row keyed MULTIPLE says so.

It is raised last, after every record that the run produces. So a caller who catches it still holds a correct graph, a complete audit trail and a compliance report that grades REVIEW_REQUIRED. The DICOM path raises after the collision report, the recoverable-identity disclosure, the delivery counters, the EXPORT audit row and Done.. The WFDB path has none of the first three. It raises after each record’s ERROR or DATA_LOSS row and its own EXPORT row.

It is a RuntimeError subclass, so except RuntimeError catches it. write_tree raises a bare RuntimeError instead, for “this serializer could not write”.

Parameters:

  • failures (list) – (entity_uid, details) per instance that failed. It is kept as self.failures.

  • attempted (int) – How many instances were planned. It is kept as self.attempted.

  • folder (str, optional) – The output folder, named in the message.

Building a graph by hand#

isocenter.Builder is the frozen name of the class below. Only start_patient() is frozen, and the chain it starts is tier 2.

Builder#

DicomBuilder#

Build a Patient graph by hand, with no files behind it.

Import it as from isocenter import Builder:

patient = (Builder.start_patient("P123", "Doe^John")
           .add_study("1.2.3", "20240101")
           .add_series("1.2.3.1", "CT", 1)
           .end_series().end_study().build())
